# Как мы работаем

## Задачи

- Любая работа начинается с issue. У issue есть исполнитель и понятный критерий готовности.
- Если за 48 часов до срока практики по задаче нет PR, любой участник может её перехватить,
  написав об этом в issue.

## Ветки

Ветка создаётся от актуального `main`, одна ветка — одна задача.

   | Тип | Формат | Пример |
   |---|---|---|
   | Новая функциональность | `feat/<номер-issue>-<кратко>` | `feat/12-job-lifecycle` |
   | Исправление | `fix/<номер-issue>-<кратко>` | `fix/15-cancel-transition` |
   | Документация | `docs/<номер-issue>-<кратко>` | `docs/5-requirements` |
   | Инфраструктура, CI | `chore/<номер-issue>-<кратко>` | `chore/8-ci-pytest` |

Имена — строчные латинские буквы, цифры и дефис.

## Коммиты

- Сообщение на русском, до 72 символов в первой строке:
  `Добавить проверку переходов Job`, `Исправить код ошибки при отмене`.
- Один коммит — одно логическое изменение. Коммиты вида `fix`, `правки`, `asdf` не допускаются.

## Pull Request

- В `main` только через PR. Прямой push и force push в `main` запрещены.
- В описании PR: что сделано, зачем, и ссылка на issue (`Closes #N`).
- PR должен быть небольшим и решать одну задачу.
- Для слияния нужно одобрение второго участника и зелёный CI (когда CI появится).
- Сливает автор PR после одобрения. Ветка после слияния удаляется.

## Review

- Ревьюер назначается в PR и отвечает в течение 24 часов.
- Проверяем: решена ли задача из issue, нет ли ошибок и пропущенных случаев,
  понятен ли код и текст, есть ли тесты на новое поведение.
- Замечания пишем по сути: вопрос, проблема или предложение с объяснением.
- Автор отвечает на каждое замечание: исправляет или объясняет, почему не согласен.
- Если ревьюер пропал, одобрение может дать проверяющая команда из перекрёстного review.

## Definition of Done

Задача считается сделанной, когда:

- [ ] выполнены критерии готовности из issue;
- [ ] изменения влиты в `main` через PR с одобрением второго участника;
- [ ] для кода: есть позитивный и хотя бы один негативный тест на новое поведение, все тесты и CI зелёные;
- [ ] для кода: нет секретов в репозитории, конфигурация берётся из окружения;
- [ ] документация (README, `docs/`) обновлена, если изменилось поведение;
- [ ] issue закрыт
