# Проверка контракта колодой

Проходим по нашему контракту картами контрактного покера К1–К10
(колода — `tasks/p2_poker/README.md` в Zadania). Для каждой карты — что вернёт API и в каком состоянии
будет задание, со ссылкой на место в контракте или на ADR.

Документы: [api/openapi.yaml](api/openapi.yaml), [tool-contract.md](tool-contract.md),
[architecture.md](architecture.md), [adr/](adr/).

## Карты

| Карта | Ситуация у нас | Ответ контракта | Где записано |
|---|---|---|---|
| **К1 Двойной клик** | Два `POST /jobs` с одним `Idempotency-Key` с разницей 100 мс | Создаётся ровно одно задание: первый запрос → `201`, второй → `200` с тем же `id`. Заголовок обязателен, без него → `400 missing_idempotency_key` | `openapi.yaml`, `POST /jobs` — описание и ответы `201`/`200`/`400`; параметр `IdempotencyKey` |
| **К2 Ответ потерялся** | Клиент получил таймаут соединения после `POST /jobs` | Клиент повторяет запрос с тем же ключом в течение 24 часов → `200` с прежним заданием в текущем состоянии. Тот же ключ с другим телом → `409 idempotency_conflict` | `openapi.yaml`, `POST /jobs` — раздел «Идемпотентность», ответ `409`; параметр `IdempotencyKey` (срок хранения) |
| **К3 Неизвестная операция** | `"operation": "dance"` | `400 unknown_operation`, в `details.allowed` — список операций; задание не создаётся, ключ не запоминается | `openapi.yaml`, `POST /jobs` — ответ `400`, пример `unknown_operation`; `tool-contract.md` — «Кто проверяет параметры» |
| **К4 Кривые параметры** | Нет `document_id`, `target_lang: 123`, `target_format: "exe"` | `400 invalid_params`, имя поля в `details.field` (например, `params.target_lang`); задание не создаётся. Параметры проверяет процессор (`validate_params`) до создания задания | `openapi.yaml`, `POST /jobs` — ответ `400`, пример `invalid_params`; `tool-contract.md` — «Кто проверяет параметры» и таблицы параметров процессоров |
| **К5 Воскрешение** | Клиент хочет запустить заново задание в `processed` или `failed` | Операции повторного запуска в API нет: конечные состояния не покидаются. Повтор — новым заданием с новым `Idempotency-Key`; прежнее задание и его результат не меняются | `architecture.md` — «Диаграмма состояний Job», таблица «Запрещённые переходы»; `openapi.yaml` — нет `retry`/`rerun` среди операций |
| **К6 Отмена** | Клиент передумал, пока задание выполняется | `POST /jobs/{id}/cancel` из `uploaded`/`queued` → `200`, `cancelled`. Из `processing` и конечных → `409 invalid_transition`, `details.status` — текущее состояние; задание продолжает выполняться. Частично сделанной работы при отмене нет: отменить можно только до начала выполнения. Повторная отмена → `200` | `openapi.yaml`, `POST /jobs/{id}/cancel`; `architecture.md` — «Запрещённые переходы» |
| **К7 Огромный вход** | Файл в 1000 раз больше обычного; огромное тело запроса; огромный текст для перевода | Файл больше 20 МБ → `413 file_too_large` при загрузке, документ не сохраняется. Тело `POST /jobs` больше 64 КБ → `413 payload_too_large`. Текст для перевода длиннее 50 000 символов → задание в `failed`, `error.code = "text_too_long"` | `openapi.yaml`, `POST /documents` — ответ `413`; `POST /jobs` — ответ `413`; `tool-contract.md` — `Translator`, таблица ошибок |
| **К8 Чужой или несуществующий id** | `GET /jobs/{id}` по несуществующему или чужому заданию | Несуществующий → `404 job_not_found`, несуществующий `document_id` → `404 document_not_found`. Чужие объекты **сознательно не закрываем**: авторизации нет, сервис для доверенной среды; идентификаторы — случайные UUID4 | `openapi.yaml`, ответы `404`; **ADR-0002** |
| **К9 Перезапуск сервера** | Сервер перезапустился, пока задание было в `processing` | При старте Dispatcher переводит такие задания в `failed` с `error.code = "interrupted"`; клиент видит это в `GET /jobs/{id}` и при необходимости создаёт новое задание. Ответ процессора, пришедший после этого, игнорируется | **ADR-0001** — «Решение»; `architecture.md` — диаграмма состояний (`processing → failed`, interrupted) и «Запрещённые переходы»; `openapi.yaml` — `JobError.code = interrupted` |
| **К10 Внешний сервис** | LibreTranslate молчит 30 с, отвечает мусором или переименовал поле | Таймаут 10 с, до 3 попыток только при таймауте, 5xx и `429` → затем `failed`, `translation_unavailable`. Остальные 4xx → сразу `failed`, `translation_rejected`. Мусор (не JSON, нет поля) → сразу `failed`, `translation_bad_response`, без повторов. Переименованное поле — для нас тот же мусор; исправляется только `TranslationClient`. Операции без перевода продолжают работать | `tool-contract.md` — «Адаптер внешнего сервиса», таблица ошибок; `openapi.yaml` — `JobError.code` |

**Итог:** 9 карт из 10 закрыты контрактом. К8 закрыта частично: несуществующие идентификаторы — `404`,
доступ к чужим объектам сознательно не закрываем (ADR-0002).

## Что предложил ИИ

**Модель:** DeepSeek

**Промпт:**

> Ты — атакующий в игре «контрактный покер». Ниже контракт нашего сервиса обработки документов
> (OpenAPI), контракт процессора и колода карт К1–К10 с нашими ответами на них.
> Найди ещё 3 ситуации, на которые контракт НЕ отвечает: конкретный запрос или событие, что должно
> вернуть API и в каком состоянии окажется задание. Не повторяй карты К1–К10 и не предлагай то,
> что уже явно описано в контракте.
>
> [далее — содержимое `docs/api/openapi.yaml`, `docs/tool-contract.md` и таблица карт из этого файла
> в версии до правок по итогам этого раздела]

**Находки и решения:**

| # | Что предложила модель | Решение | Почему и что изменили |
|---|---|---|---|
| 1 | `translate` с `source_lang: "english"` — проверка описана только для `target_lang`, что делать с мусором в `source_lang`, не сказано | **Приняли** | Мусор ушёл бы во внешний сервис и вернулся непонятной ошибкой. В `tool-contract.md` (`Translator`) и `openapi.yaml` (`CreateJobRequest.params`) записали: переданный `source_lang` проверяется как `target_lang` → `400 invalid_params`, `details.field = "params.source_lang"`, задание не создаётся |
| 2 | LibreTranslate отвечает `429` или `400` — для 4xx нет ни кода ошибки, ни правила повторов | **Приняли** | Разделили: `429` — временная перегрузка, повторяем как 5xx (пауза из `Retry-After`, не больше 10 с). Остальные 4xx — повтор даст тот же отказ, поэтому сразу `failed` с новым кодом `translation_rejected`, HTTP-статус — в `error.message`. Изменили `tool-contract.md` (адаптер, таблица ошибок), `openapi.yaml` (`JobError.code`) и карту К10 |
| 3 | `convert` PDF → PDF: `target_format` валиден, но пары конвертации нет — непонятно, что вернуть | **Приняли частично** | Записали список поддерживаемых пар и новый код `unsupported_conversion`. Отклонять при `POST /jobs`, как предложила модель, не стали: `validate_params` получает только параметры, а формат документа становится известен после проверки `DocumentValidator`. Поэтому задание создаётся и переходит в `failed` с `unsupported_conversion`. Изменили `tool-contract.md` (`FormatConverter`, таблица ошибок) и `openapi.yaml` (`JobError.code`, описание `params`) |
